# AX.25 packet via AGWPE (as used by HamBBS)

HamBBS runs over AX.25 connected mode through any TNC with an AGWPE TCP
interface: **Direwolf** (Linux, Windows, Raspberry Pi), **UZ7HO
soundmodem** (Windows), AGWPE itself, or hardware TNCs behind an AGW
server such as ldsped. The TNC does the AX.25 work (connect, I-frames,
acknowledgements, retries); HamBBS sees one byte stream per session and
the callsign of the station on the other end.

One TNC connection carries any number of sessions at once, so several
users can be connected to the BBS at the same time.

## Frames HamBBS uses

Every AGWPE frame has a 36-byte header (radio port, kind, PID, from and
to callsign, data length), followed by the data.

| Kind | Direction | Use |
|---|---|---|
| `G` | both | ask for the TNC's radio ports; the server checks `port` exists |
| `X` / `x` | to TNC | register / unregister a callsign the BBS answers on |
| `C` | both | connect request; from the TNC: link up |
| `v` | to TNC | connect through digipeaters |
| `D` | both | session data, PID 0xF0, at most 256 bytes per frame |
| `Y` | both | frames still queued or unacknowledged for one session |
| `d` | both | disconnect request; from the TNC: link down |

In `C`, `D` and `d` frames from the TNC, *from* is the remote station. Its
callsign comes from the radio link, so the BBS uses it as the verified
callsign, as with VARA.

## Flow control and disconnect

* `Write` sends at most 8 frames ahead. Then it asks the TNC with `Y`
  how many are outstanding and waits until fewer are left. A dropped link
  then loses little, and a long upload doesn't fill the TNC's memory.
* **Direwolf discards queued data when asked to disconnect.** Before
  sending `d`, HamBBS therefore waits until `Y` reports 0 outstanding
  frames. It gives up after two minutes without progress.
* A TNC that never answers `Y` still works, but the end of a session may
  be cut off. HamBBS logs a warning when this happens.

## Addresses

The client's address is the BBS callsign, optionally with up to seven
digipeaters:

```
LA1BBS
LA1BBS-1
LA1BBS via LA2DIG
LA1BBS v LA2DIG,LA3DIG
```

AX.25 callsigns have at most 6 characters plus an SSID of 0–15.

## Speed

1200 baud AFSK moves about 100 bytes per second once you count frame
overhead, acknowledgements and TX delay. A sync with nothing new is
about 350 bytes, so roughly 5–10 seconds. The client allows a whole sync
30 minutes over AX.25 (10 minutes otherwise). On slow links, fetch
bulletin headers only and pick the bodies you want.

## Testing without a radio

Package `internal/transport/agwpe/agwpetest` is a set of mock TNCs on a
shared simulated channel, with configurable speed and latency. It
behaves like Direwolf where it matters for HamBBS: connect replies,
`RETRYOUT` when nobody answers, `Y` counts, and a disconnect that drops
queued data. `internal/client/ax25_test.go` runs full BBS sessions
through it, including a terminal user and a sync client at the same
time.
